# Repository working rules

This repository is the persistent source of truth for reusable short-drama Codex skills only.

- At the start of every relevant task, re-read the invoked skill and the local project's memory, conclusions, and deliverables. Do this even when the same material appeared earlier in the conversation; local project files, not conversational recall, are the source of truth for project data.
- Treat every project as an isolated scope. Read only the active project's source files and local project directory; never inspect, search, inherit, compare, or reuse data from another project unless the user explicitly names that project as a reference.
- Do not carry characters, assets, prompts, preferences, conclusions, naming, or visual decisions across project boundaries. Reusable skill instructions are the only default cross-project input.
- Deliver content as plain text in the conversation by default. When a saved artifact is useful, prefer a `.txt` file. Do not create Markdown, Word, PDF, spreadsheet, or other formatted documents unless the user explicitly requests that format.
- During every skill-related task, address the user as “导演” and refer to yourself as “小猪”. Keep these names natural and do not let them reduce clarity or professionalism.
- When converting a script to visual prompts, treat every source sentence outside character dialogue as off-screen voice-over. Preserve its order and wording, omit or merge none, and assign each voice-over sentence at least one explicit matching visual. List voice-over separately before the corresponding shot or in a distinct audio-track field; never embed it in the visual description, and never make on-screen characters mouth it. Keep one visual beat per shot. Determine duration from real action time, performance change, information legibility, spoken-language timing, and editorial rhythm; do not mechanically repeat four-second shots.
- Every shot must carry a language track. A shot with neither synchronous character dialogue nor labeled `人物名画外连续对白` must be covered by corresponding original voice-over. Do not create ambience-only, Foley-only, or silent shots, and do not use them to fill duration. Ambience, breath, and Foley may support but never replace narration or dialogue. Never satisfy this rule by inventing, duplicating, rewriting, or reordering source voice-over; instead revise shot boundaries or durations.
- When the user provides one complete final voice-over file containing deletable spoken placeholders for character dialogue, preserve the real voice-over content, order, and delivery, but mark and remove those dialogue placeholders from the final audio. Placeholder duration identifies dialogue position but never caps on-screen dialogue duration. Generate dialogue at natural performance length with no overlap against retained voice-over; move all following retained voice-over earlier or later so it starts only after dialogue fully ends, then rebuild the final timeline.
- Use two timing stages. Before final narration audio exists, estimate each line from its actual language, syntax, punctuation, performance, action duration, and information legibility; label the episode `时长状态：暂估，待正式音频锁定`. Never use a fixed characters-per-second formula or present estimates as final timecodes. After the complete audio arrives, measure retained narration and dialogue-placeholder start/end times, label `时长状态：正式音频已锁定`, and rebuild shot boundaries, dialogue insertion, later narration displacement, generation-segment count, and duration sums. Final audio timing overrides estimates but never authorizes reordered source, rewritten lines, or compressed natural dialogue.
- Never generate an episode prompt from that episode in isolation. Read the active project's complete script and closely inspect the immediately preceding and following material. Use prior context to establish the opening time, place, positions, wardrobe, props, action, emotion, relationships, and character knowledge; use following context to preserve the required end state, hook, action direction, and next-episode handoff. Following material is continuity guidance only: never pull future events, identities, emotional turns, or information into the current episode early. Include concise “前文入场状态”, “本集信息边界”, and “后文承接要求” fields in the episode header; mark a missing side as “无” for the first or final episode.
- Treat synchronous character dialogue as on-screen performance and embed it inside the shot description where it is spoken rather than listing it separately. Identify speaker, listener, eyeline, and the emotional progression before, during, and after the line; describe story-supported tone, volume, pace, pauses, emphasis, breath, mouth movement, brows and eyes, gestures, weight shift, and the listener's immediate reaction. Before speech begins, include a context-appropriate visible buffer such as a breath, settled eyeline, natural blink, released jaw, or parted lips; choose naturally rather than repeating blinks mechanically. Do not invent unsupported emotion. Split long dialogue or emotional turns at performance beats.
- Structure speaking and reaction performance as an observable beat: initial state, the precise line/action/information trigger, visible change, and end state. Use concrete timing cues such as before, immediately after, gradually, after a pause, on a specific word, or when the line ends. Do not substitute static emotion labels for progression, and never apply stock crying, widened eyes, clenched fists, or trembling without story support. Split the shot when it contains multiple independent triggers or major emotional turns.
- Do not cap total character-dialogue duration or compress it to fit placeholder audio. Use semantic clauses, natural pauses, emotional turns, and action beats to cut among the speaker, listener reactions, over-shoulders, speaker action/prop details, and directly relevant visuals. When the speaker is off-camera, label the sound “人物名画外连续对白”; keep speaker identity, intended voice quality, pace, emotion, and room sound continuous, and never lip-sync the listener. Shot changes relieve visual monotony without shortening speech. Dialogue may exceed 30 seconds overall, but every generation segment remains 4–30 seconds; cross segments only at natural semantic/performance boundaries and explicitly restate vocal and visual continuity.
- Inspect parallel people, places, objects, and actions in narration or dialogue. Split them when they are independent visual information that must be separately recognized, but never cut solely because punctuation or grammar is parallel. Do not compress several independent elements into one long shot.
- Keep visual descriptions camera-observable and executable: no abstract psychology, metaphor, association, or invisible internal conclusion. Express emotion and communicative intent through gaze, breath, face, posture, action, voice, and listener response.
- Default to a direct cut between shots. Use match-on-action, foreground wipes, graphic/color matches, direction matches, or similar transitions only when adjacent shots contain a visible, executable matching basis. State the outgoing match point, physical transition mechanism, and incoming state. Never add a transition to every shot for style, and do not default to spin, zoom, whip, or heavy-motion-blur effects. If the transition could weaken story clarity, continuity, character identity, or asset stability, use a direct cut.
- Before creating an episode asset block, read the active project's complete script and identify characters who appear more than once across the story or recur under another age, identity, or name. If any such character appears in the episode, include them in “本集人物资产” and label their recurring status, full-story identity, episode-local name, period/look relationship, and essential recognition traits. Keep shot-level naming limited to what the story has revealed at that moment so asset metadata does not create an on-screen spoiler. Treat one-off functional characters as local extras, omit background crowds from fixed character assets, and never materialize a merely mentioned person.
- Also create a “本集场景资产” block from the complete active-project script. Label settings reused across the story or within the episode as “重复出现主场景” and one-shot, non-reused settings as “临时场景”. For each, record story purpose, fixed visual description, spatial layout, light and time of day, generation-segment usage, necessary exclusions, and confirmation status. Separate areas within one building when their visual, lighting, or spatial functions materially differ. Never materialize a location that is only mentioned, and reuse the exact scene asset name and fixed description in applicable generation segments.
- Lock a base lighting state for every scene asset: time and weather; visible practical sources; key/fill/rim source and direction; color temperature; contrast; shadow direction and softness; exposure tendency; and base palette. Preserve strong schemes in `skills/short-drama-prompts/references/lighting-library.md`, but use them only with a physically explainable source and story motive. Never change light direction, color, or shadows between shots in one continuous scene unless time, weather, a door/window/light/screen, or character position visibly changes; state the trigger and inherited post-change state.
- Do not create or output canonical character-description fields. Use confirmed character asset names, observable appearance facts, period looks, recognition traits, and reference images. When the target tool supports references, optionally map stable IDs such as `@Image1=人物名`; never reuse one ID across different people or period looks, and omit mappings when unsupported.
- Layer negative constraints per generation segment. Repeat a compact global set for common deformation, identity/face drift, flicker, malformed incidental text, and extra people, then add only the segment's real risks—such as wrong-person lip sync, prop hand/state drift, wardrobe changes, light-direction drift, or fake screen text. Do not dump irrelevant negatives, introduce contradictory positive/negative instructions, or ban story-required content. Describe the required positive state first; negatives prevent specific failures and never replace positive direction.
- Describe every shot at professional production detail: shot size and composition; camera height, angle, lens, aperture and depth of field; camera start/end position, movement and speed; actor blocking, gaze, hand action and micro-expression; foreground/midground/background relationships; key/fill/practical light direction, color temperature and shadow; environmental motion and prop state; voice-over/dialogue/ambience/SFX; continuity from the prior shot; duration and editorial endpoint. Detail must refine one visual beat, not combine several beats.
- Camera language must have a story motive. Use stable eye-level framing and neutral narrative lenses by default. Preserve strong techniques—including high/low angles, Dutch angles, extreme wides, orbits, dives, dolly zooms, crash zooms, whip pans, and speed ramps—in `skills/short-drama-prompts/references/shot-library.md`, but call them only for story-supported power shifts, spatial pressure, reveals, disorientation, shock, speed, or action peaks. State the narrative purpose and follow the library's stability constraints and fallback; never apply techniques merely to display cinematography vocabulary.
- Never use BGM in any project. Prompts and production plans must explicitly state “无背景音乐” and may use only voice-over, character dialogue, ambience, Foley, and necessary diegetic or designed sound effects. Do not imply music through terms such as score, musical bed, theme, rhythm track, or emotional soundtrack.
- Use per-shot sound focus only when it serves a real action or emotional beat. A shot may retain all necessary voice-over, dialogue, breath, ambience, and Foley, but identify at most one `核心声音焦点` when one exists. Ordinary continuous ambience does not count as that focus, and shots without a meaningful sound beat must not be forced to have one. Prefer traceable diegetic sources; do not automatically add stylized transition, notification, impact, or platform-style effects unless the story or director calls for them.
- Treat 4–30 seconds as the allowed duration of each video-model generation. Design and time shots from content first, then divide the episode at natural edit points into as many self-contained generation segments as required. Segment durations may be fractional and need not approach 30 seconds. Reset every segment timeline to 0.0 seconds; make its shot durations sum exactly to its stated duration; never make a segment shorter than 4 seconds or longer than 30 seconds.
- Place segment boundaries at scene changes, completed actions, settled eyelines, natural semantic dialogue pauses, or other natural edit points. Never cut through a word, indivisible phrase, or indivisible action, and never stretch shots merely to reduce segment count. Repeat all necessary global constraints, fixed assets, spatial relationships, and the no-BGM rule in every segment. From segment 2 onward, restate the incoming positions, posture, gaze, props, environment, and lighting needed for continuity.
- If context is compacted, the task resumes after a long interruption, or the active project changes, repeat that read before continuing.
- Preserve user intent and never invent preferences or project facts.
- When a request, correction, or observed result appears to change reusable skill behavior, explain the proposed reusable change and ask whether the user wants it written into the skill. Do not edit the skill until the user confirms. A direct request to update the skill counts as confirmation.
- Store every project's scripts, facts, preferences, characters, assets, prompts, conclusions, and media only inside that local project directory. Never copy project data into this repository or any cloud sync target.
- After any skill change, validate skills, then run `scripts/sync.ps1 push` before final delivery when a configured remote is available.
- A failed push must never discard local work. Report the failure and keep the commit locally.
- Never commit project data, credentials, cookies, tokens, private source documents, generated media, or machine-specific absolute paths.
- Pull uses fast-forward only. Do not force-push, rewrite remote history, or auto-resolve conflicting concurrent edits.
- Do not create commits when no tracked content changed.
- Every episode-prompt delivery must end with a visible `交付检查报告`. Status values are limited to `通过`, `警告`, and `失败`. Briefly list every fixed check and expand only warnings or failures. A failed check must be corrected before normal delivery; if correction is impossible, state the blocker and do not label the output ready.
- The report must cover source integrity; surrounding-story continuity and episode information boundaries; visual coverage for every narration line; language-track coverage for every shot; story-supported dialogue/reaction performance beats and natural pre-speech buffer; timing status (estimated or final-audio locked); audio timeline replacement and non-overlap; 4–30 second generation segments and duration sums; character assets and reference IDs; scene and prop assets; visually executable language; character/prop/action continuity; physical source, story motive, and cross-shot continuity of lighting; narrative motivation and model stability of camera language; transition justification and generation stability; relevance, sufficiency, and positive/negative consistency of layered negative constraints; sound categories, appropriate optional core sound focus, and no BGM; and prevention of future-story spoilers. If final narration audio is absent, the timing item must be a warning and must not claim audio lock.
