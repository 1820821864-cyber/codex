# Codex Short Drama Director

面向 Codex 的短剧创作技能仓库，参考 `my401367513-creator/deepseek` 的模块化思路重新设计，不依赖 DeepSeek Desktop 专属组件。云端仅保存可复用技能；所有项目数据仅保存在各自的本地项目目录。

## 结构

- `skills/short-drama-script-analysis`：剧本诊断与人物档案
- `skills/short-drama-assets`：人物/场景/道具/音频资产库
- `skills/short-drama-prompts`：AI 视频提示词
- `scripts/sync.ps1`：安全拉取、提交与推送

相关对话产生确认过的通用技能改进后，Codex 更新技能并执行同步脚本。同步只发生在技能相关文件实际变化时；项目内容永不进入仓库。冲突或网络失败会保留本地提交并停止，不会强推。

每次执行相关任务，Codex 都重新读取技能和本地项目目录中的项目记忆、档案与已有结论。新的要求若可能改变通用技能行为，会先询问用户是否要沉淀为技能更新；确认后才修改并同步仓库。

项目之间默认完全隔离：新剧本只读取通用技能、当前剧本和当前项目目录，不读取或继承任何往期项目内容。只有用户明确点名某个往期项目作为参考时，才允许跨项目读取。

交付默认直接在对话中使用纯文本显示；需要保存时优先生成 `.txt` 文件。只有用户明确要求时才创建 Markdown、Word、PDF、表格等其他格式。

执行技能相关任务时，称呼用户为“导演”，助手自称“小猪”。

剧本转提示词时，除人物对白外的每一句原文都作为旁白，保持原顺序与原措辞，并逐句配置画面。镜头通常控制在约1.5–4秒和一个视觉动作；长旁白拆成多个短镜头，不用冗长单镜头承载。

每个镜头采用专业制作级描述：构图、机位、镜头参数、运镜起止与速度、人物走位和微表情、空间层次、布光、环境与道具、声音、连续性、时长和剪辑落点必须明确；详细不等于把多个视觉动作合并进一镜。

人物对白开口前加入符合情境的自然可见缓冲；并列人物、地点、物品或动作只有在属于独立视觉信息时才拆镜；画面描述只写可见、可听、可执行内容。支持参考图的工具可选用稳定的 `@ImageN=人物名` 映射。人物资产不建立或输出 canonical 描述字段，改用已确认的外观事实、时期造型、识别特征和参考图。

整集正式旁白音频可包含后期删除的人物对白占位旁白；占位长度不限制画内对白。对白按自然表演完整生成且不得与正式旁白重叠，实际时长变化时后续旁白随之重排。长对白用说话者、倾听者、过肩、动作/道具特写和相关画面交替承载；说话者离画后标注画外连续对白，镜头切换只解决视觉冗长，不压缩台词。

画外旁白作为独立音轨文字列在对应镜头之前，不写进画面描述，画中人物也不为旁白匹配口型。人物对白则是画内表演，直接嵌入对应镜头，并细化说话者与对象、视线、开口前后情绪、语气、音量、语速、停顿、重音、呼吸、嘴部与眉眼、手势、身体重心、潜台词和对方即时反应。

制作单集人物资产前先通读当前项目完整剧本。凡在全剧出现一次以上，或以不同年龄、身份、称谓再次出现且本集出场的人物，均列入“本集人物资产”，标注重复身份、本集称谓、时期/造型对应和核心识别特征；镜头仍按当时剧情称谓呈现，避免提前泄露身份。

单集提示词还必须建立“本集场景资产”：区分重复出现主场景和临时场景，记录关联剧情、固定视觉描述、空间定位、光源与时段、使用范围、必要限制和确认状态；同一建筑内视觉或空间功能明显不同的区域可拆分，生成段复用相同场景名称和固定描述。

单集提示词同时结合前文和后文：前文用于确定开场的人物、空间、服装、道具、动作、情绪和已知信息，后文用于确定本集结尾状态、钩子与下一集承接。后文只服务连续性，不得提前引入尚未发生的剧情或身份揭晓；提示词词头明确列出前文入场状态、本集信息边界和后文承接要求。

所有项目全片禁止BGM。声音仅允许旁白、人物对白、环境音、拟音和必要音效；提示词与制作方案必须明确写出“无背景音乐”，也不得用配乐、铺底、主题音乐等措辞暗示BGM。

单镜声音按需聚焦：镜头可保留必要对白、呼吸、环境底声和拟音，仅在动作或情绪落点确有需要时标注至多一个“核心声音焦点”。普通环境底声不占焦点，无明确声学落点时不强行配置；优先使用画内可追溯声源，不默认添加风格化平台音效。

视频模型每次生成限定为4–30秒。系统先按动作真实时长、表演变化、语言语速和剪辑节奏设计长短有变化的镜头，再在自然剪辑点拆成多个可独立执行的生成段；不得机械重复4秒镜头或为凑整段而修改镜头。每段时间轴从0开始，镜头时长总和与段时长一致，并重复必要资产、空间关系和无BGM约束。

每次正式交付单集提示词时，末尾必须附带可见的“交付检查报告”：全部固定项目均列出，状态仅为“通过 / 警告 / 失败”，仅对警告和失败展开说明；存在失败时先修正，无法修正则明确阻碍，不把结果标为可用。
